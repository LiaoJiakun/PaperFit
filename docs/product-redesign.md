# PaperFit 完整改版方案与验收范围

日期：2026-11-06。目标用户：一般生物医药行业从业者，包括研发、医学和行业研究岗位。核心任务是围绕问题发现、筛选、复核有参考价值的文献，交付可追溯的阅读清单。市场扩大是待验证的产品假设，不能以覆盖岗位数代替真实用户验证。

## 产品闭环

首页提供体验、新建研究和历史记录。体验使用真实论文的离线结果，不消耗额度、不覆盖用户任务。新建研究支持自动检索和上传 PDF；输入问题后可让 AI 建议条件，用户直接新增、删除、编辑条件并选择重要性。点击确认才会启动检索和筛选。结果先给阅读建议与理由，再展开原文证据。用户可改条件重跑、重试单篇、导出或回到历史。

## 条件和判断规则

- 不再强制四项 PICO。AI 建议 3–6 项，可手工填写 1–12 项，名称不可重复。适用于疾病研究、方法比较、AI 药物研发等问题。
- 默认“优先考虑”。偏好不匹配仍可作为背景参考；“必须满足”只有可定位证据明确证明不匹配时才标记“不符合必须条件”。
- 没有找到证据、原文获取失败、只有摘要，均保留为待核查，不能当作明确排除。
- 阅读优先级、相关性、证据状态、条件符合情况分开显示。“引文已定位”只表示字符位置核验通过，不等于研究质量高或结论正确。
- 综述等二次文献用于背景参考；自动检索不是系统综述，不宣称穷尽。保留查询词、候选记录和每篇理由。
- 确认后的条件驱动检索与核查。修改问题后提示重新核对条件；不会悄悄替换用户条件。

## 信息架构与交互

| 页面 | 主要内容 | 主要操作 |
| --- | --- | --- |
| 首页 | 产品用途、离线体验、最近研究 | 体验、新建、继续 |
| 研究设置 | 问题、来源、动态条件、必选/偏好 | AI 建议、增删改条件、确认开始 |
| 阅读清单 | 版本与状态、计数、分组、理由、证据 | 修改条件、重试、导出 |
| 历史记录 | 任务标题、更新时间、版本 | 恢复草稿、打开版本、删除 |
| 证据核查 | 条件判断、原文引文及位置 | 返回清单、打开原文、重试 |
| 模型设置 | DeepSeek 密钥、本机保存说明 | 保存密钥 |
| 侧栏 | 固定导航、工作区说明 | 首页、新建、历史、模型设置 |

运行中显示阶段和进度；单篇失败继续其他论文。保存每个已完成结果和过程记录。中断版本仍可打开；不会虚构后台继续或自动恢复正在执行的网络请求。重试与重新运行产生新版本，原版本保留。

## 数据与版本

本机 ~/.paperfit/history.sqlite3 保存任务、草稿、版本和执行记录；上传文件复制到 ~/.paperfit/files，以内容哈希去重。刷新或重新启动后可从历史恢复。输入框失去焦点、条件重要性改变时保存。新建任务不删除旧任务；删除须确认并清理不再被其他任务/版本引用的文件。密钥独立配置，不写入历史或报告。当前只支持本机、单人使用。

每个任务有可继续编辑的草稿和多个不可被重试覆盖的结果版本。运行内部可更新同一版本的进度检查点。打开旧版本显示当时条件，继续修改以该版本为起点；运行后生成另一版本。体验不写进历史。

## Agent 边界

Agent 可规划检索词、检索候选、摘要排序、获取开放全文、逐项核对并尝试一次修正引文；用户决定研究问题、条件和重要性。执行预算继续采用每次最多 30 条候选、5 篇全文核查，上传最多 20 篇。检索覆盖 Europe PMC 当前收录（含预印本），并非只限定 PubMed，也并非覆盖所有论文库。

本期不加账户、云同步、团队权限、定时追踪、自动综述或 OCR。扫描 PDF 提示用户自行做文字识别再上传，不静默启动识别。

## 验收

1. 体验无模型调用，真实任务不被体验覆盖。
2. AI 抗体研发问题可以使用方法/研发环节等动态条件；最终编辑值传到检索和核查。
3. 必须条件明确不符与证据不足分开；偏好不符保留。
4. 草稿、文件和结果在新会话可恢复；新任务不删除旧任务。
5. 重跑与重试保留旧版本；失败检查点可打开。
6. 删除任务清理独占文件、保留其他任务共享文件；历史不含密钥。
7. 导出包含条件重要性、证据和版本状态。
8. 自动化检查和真实浏览器检查通过，交付运行页面与 FigJam 流程。

后续产品验证：邀请不同岗位的 3–5 位从业者用真实问题完成一次任务，观察能否独立形成清单、推荐是否值得阅读、证据定位是否方便、是否会返回历史继续。先记录基线，再设定量化改进目标。

- [Figma 可编辑界面](https://www.figma.com/design/S3vnBBNd75RVTfuQikGvZN)：首页、研究设置、阅读清单、证据核查、历史、运行中、部分失败、空状态、模型设置、删除确认共十个界面。1440px 桌面画板，中文使用 Noto Sans SC，深绿强调色与中性背景。
- [FigJam 完整业务流程](https://www.figma.com/board/sEEPCGYYe5PNiFU8RT0QB2)：最终版本与早期讨论图同文件保留。
- 可复用组件：SDS 按钮、标签和输入框实例；PaperFit 论文卡片与分组统计组件。
- 原型展示页面间导航；输入、筛选、网络请求和本机持久化在源码应用中执行。本地应用已实现同样的独立证据页、模型设置页与删除确认页，采用相同字体、配色、卡片、间距与导航。桌面以 1440px 设计为基准，并适配更窄窗口；真实数据的文字长度和状态决定页面高度。
